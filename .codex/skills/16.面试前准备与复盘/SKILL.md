# 面试前准备与复盘

## 触发条件

自动触发，但入口窄，只认下面两类指令：

1. **面试前**——用户发来一份新岗位 JD，且要求做面试前的准备工作（如「帮我做面试前的准备工作」「按这个 JD 帮我准备」）→ 执行「一、面试前准备」。
2. **面试后**——用户说「本轮面试结束了」（或同义的「这轮面完了」「面试结束了」）→ 执行「二、本轮面试复盘」。

用户点名本 skill 名称或目录名时也激活。

**不要因为用户提到简历、JD、面试、岗位这些词就激活。** 本技能会实际改动文件（改简历副本、填写与重置 steering、写归档），误触发的代价比漏触发大。两种典型的不该激活：

- 用户只贴了一份 JD、没说要准备 → 先问一句要不要跑准备流程，不要自己开始。
- 用户在问某道面试题该怎么答 → 那是 `04.项目经验` 等答题类 skill 的事，与本技能无关。

---

## 一、面试前准备（收到新 JD + 「帮我做面试前的准备工作」）

先做一件事：从 JD 里提取出「公司名、目标岗位、岗位职责、技术关键词、业务领域、上下游团队」六项，作为后续三步的共同输入。公司名用于命名简历增补文件与问答归档目录，其余五项用于填 steering 和写自我介绍。

### 步骤 1：补简历里缺失的麦当劳部分

**唯一产物：增补版** → `.private/简历增补/<公司名>.md`（`.private/` 已 gitignore，不进公开仓库）。**只写相对基线新增的内容**，不复制基线原有段落。完整简历由本人据此自行排版投递，不要生成。

按「补在哪里 + 补什么」组织，每段标明插入位置，方便本人直接对位粘贴：

```
## 近期主要项目经验 · 第 1 项（新增：麦当劳）
<完整的新增条目>

## 工作经验 · 麦当劳第 3 条 bullet（仅调能力词顺序，附调整理由）
<调整后的该条>
```

改动前先读三个事实底座，不要凭印象写：

- `.private/项目经验库.md` 第二章「麦当劳中国」——素材来源
- `.private/面试主线整合版.md`——问题到案例的映射、归属口径
- `.private/简历-上次跳槽版.md` 文末「校对清单」——已定的时间线、姓名、归属、数字口径

**硬性约束：**

- **术语先对齐，下文一律按这个说。** **条目** = `###` 那级，即「1、麦当劳中国 · 用户营销活动平台」这一整块；**子项** = `####` 那级，即 1.1、1.2、1.3；**bullet** = 1.1.1、1.1.2 那级。下文说「每个子项一条收益」指的是 1.1 一条、1.2 一条，**不是**每条 1.1.x 后面跟一条。
- **不动格式，且字段要写齐。** 层级、标号、加粗位置全部沿用基线里天猫好房那条。**沿用格式就得沿用它的完整字段，别只挑好写的写**——天猫好房那条的真实结构是：

  ```
  ### 1、<公司> · <平台名>
  **项目简介**：<四件事 + 钩子>
  **技术组成**：<技术栈罗列>
  #### 1.1 <子项名>
  <引导段：背景痛点 + 我的角色 + 团队规模 + 投入周期>
  - 1.1.1 <亮点>
  - 1.1.2 <亮点>
  **收益**：<该子项的量化结果>
  **未来挑战**：<该子项还没解的问题>
  #### 1.2 ...（同上，每个子项独立带收益与未来挑战）
  ```

  **四个字段都是必填：引导段、bullet、收益、未来挑战。** 引导段是招聘方判断「你到底干了什么、带了几个人」的唯一依据，漏了就显得只是参与者；未来挑战体现还在往前看，也是面试官最爱顺着问的钩子。收益与未来挑战都**按子项各写一条**，`####` 有几个就各有几条，不存在多个子项共用一条的写法。
- **主产物是「近期主要项目经验」里的麦当劳条目**，把它作为第 1 项，天猫好房及之后顺延。
- **`## 工作经验` 下的麦当劳 4 条 bullet 不重写。** 那几条讲的是角色、团队规模、绩效、CR 与面试职责，与 JD 无关。唯一可动的是「高可用、强一致、低延迟、防黑产」这串能力词的**顺序与侧重**——按 JD 把最相关的提到前面（资金类岗位提强一致，中台类岗位提通用能力沉淀）。只调顺序，不加内容、不改事实。
- **技术组成要用招聘方认得的通用名词打头，内部形态放括号**。三条具体规则：① 容器编排写 **K8s（TKE/ACK 双集群 + 云下 RKE）**，不要只写 TKE/ACK——初筛的人不一定认得云厂商的托管名，但一定认得 K8s；② 内部基础库**不写代号**（脱敏表已把 c8s 列为需脱敏），写成「Spring Boot（含自研公共框架库：trace 全链路透传、带 trace 的线程池与 HTTP 客户端族）」，既保住 Spring Boot 这个关键词又带出基础库沉淀这个亮点；③ 服务网格 istio 要写上，它是加分项且本人踩过 istio-proxy OOM。**注意 Spring Boot 与 K8s、基础库不是同层的东西，三者并列不冲突**，被问到时能说清分工：Spring Boot 是应用框架、基础库管 trace 与横切能力、K8s 管部署编排。
- **重 Loyalty，轻 CNN。** 本人是 Loyalty 组负责人，简历重心必须在 Loyalty：会员营销活动、玩法容器、券与促销、任务编排、发奖、微页面。CNN 私域触达只作为佐证出现。
- **CNN 占比按字数卡，不超过 20%。** 即新增的麦当劳项目条目里，CNN 私域触达相关字数 ≤ 该条目总字数的 20%。写完要自己数一遍。
- **项目简介段写四件事，并留钩子**：项目定位（是什么、在整个链路里的位置）、面向人群（对客还是对内、什么规模量级）、业务难点、亮点设计。**钩子指的是点到而不展开**——只报结论和技术名词，把「怎么做到的」留给面试官问，他一问就转 `04.项目经验` skill 接着答。
- **详细介绍合计约 950 字**（900 到 1000），跟基线天猫好房那条实测的 948 字对齐。子项 3 到 4 个。

  **子项不要求等长，照基线的真实形状写**：天猫好房三个子项是 507、259、182 字，最贴岗位的那个是主力子项、撑起一半篇幅，其余两个收着写。所以挑一个与 JD 最对口的做主力，写到 400 到 500 字、bullet 可以到六七条；其余子项 180 到 300 字、bullet 三到四条。四个字段仍然一个不能少。

  **主力子项 = steering「本轮优先案例」第 1 条**，也就是 `04.项目经验` 选案例时的首选主案例，三处保持一致。**麦当劳是当前在职这段又排在第 1 项，篇幅明显短于第 2 项，读起来就是「最近两年没产出」。** 简历不是口述答案，招聘方是拿着 PDF 逐条读的，篇幅本身就是信息量信号。

  子项内部仍要克制：bullet 每条一句话，只挑与 JD 技术关键词重合的亮点，不要把项目经验库里的细节全搬上去。**该省的是单条 bullet 的长度，不是字段和子项。**

**口径纪律（必须遵守，来源见校对清单）：**

- **交付状态与数字一律按经验库现有口径写**，不要退回早期文档里「压测待评估」「设计目标」这类保留说法；经验库已确认交付的就按已达成写。
- AI／MCP 必须区分「已落地」与「设计方案」，不能混作一谈；哪些算已落地按经验库的判定写，别自己升格。
- OKR 里的目标值属于待达成，不能当成果写。
- 用户规模有三层口径（去重实名会员 / 可触达账号 / 容量设计基线），**别混用，具体数字以经验库为准**；简历上用哪一层都行，但要跟答辩口径对得上。

### 步骤 2：填写 steering 的「本轮目标岗位」

**岗位信息只有一个填写处**：`.kiro/steering/01.基础知识.md` 的「本轮目标岗位」一节。它是 `inclusion: auto`，每轮对话都注入，所以 04、06、07、08、09 全部能读到，不需要在各 skill 里各存一份。

按 JD 填十一项：本轮面试轮次、本轮面试官定位、招聘企业、目标岗位、岗位职责、候选人定位、岗位技术关键词、业务高频词、上下游协同团队、本轮优先案例、本轮要避开的。

填写要点：

- **岗位职责**别照抄 JD 全文，提炼 2 到 4 条、每条一句话，**保留 JD 原词**（面试官会用自己 JD 里的词提问）。
- **业务高频词**是答题时要主动用的词，从 JD 里摘，不要用自己团队的内部叫法。
- **本轮优先案例**填 3 到 5 条「问什么 → 挑哪个案例」的映射，案例必须来自 `.private/项目经验库.md`，不能凭印象编。挑的时候优先找与 JD 技术关键词重合度最高的，同时**主动找出与 JD 领域直接对应的那一段经历**（哪怕体量小、年代久），一条也要留位置。复盘时重置为 TODO。
- **本轮要避开的**要写清「哪些方向没做过」+「被问到怎么答」，避免临场硬撑。
- **本轮面试轮次**决定用哪条优先级链（四个值与链见通用规则的「规则优先级」）。**本轮面试官定位**决定同一条链里往哪儿使劲（技术主管追实现、交叉面试官防标准套用、CTO 只到判断层、HRBP 不碰技术）。这两项都是 JD 里读不出来的，用户没说时**各问一句**，不要替他猜。

**steering 之外，`08/09.HRBP` 的「高频问题与标准口径」里也会有按轮次填的 TODO**（同一个占位串）。08 与 09 写同一段，落到对方的具体业务，不写换个公司名也成立的通用话。

填完 grep 一遍 `TODO（面试前填写）`，确认 `.kiro/` 下已无遗漏。

### 步骤 3：写一版契合 JD 的自我介绍

写进 `.private/简历增补/<公司名>.md` 末尾，单开一节「自我介绍」。给两个版本：

- **30 秒版**，约 120 字，用于对方说「先简单介绍下自己」
- **90 秒版**，约 350 字，用于对方说「详细讲讲你的经历」

**先按「本轮面试轮次」决定要不要贴目标岗位**（轮次见 steering「本轮目标岗位」）：

- **技术一号位面 / 常规技术面**：自我介绍要有 JD 匹配度，按下面的四段走，第 2、4 段紧扣目标岗位。
- **CTO 面 / 交叉面**：**不贴目标岗位**，按经历正常介绍即可——学历背景、几段经历各做了什么、当前定位、研发与管理的精力占比。CTO 面看的是格局和综合面，硬贴 JD 反而显得局促。参考本人三年前那版的骨架（学历与专业 → 三段经历各一句职责与角色 → 当前这段的具体分工 → 研发/管理/学习的精力占比如 7:2:1），把项目和职级替换成最新的即可，不强行往目标岗位上靠。

四段走（技术一号位面用）：

1. **一句话当前定位**——现任职级与负责的域，带上业务量级
2. **两个与 JD 最强匹配的锚点**——从 JD 的技术关键词和业务领域里挑最硬的两项，各配一个自己的真实项目，一句话带结果
3. **一个反差亮点**——JD 没要求但对方一定感兴趣的，用来制造记忆点（如资金安全体系、AI/MCP 落地、团队级机制建设）
4. **一句为什么是这家**——必须落到 JD 里的具体业务，不能是「贵公司平台大」这类通用话

要求：口语化，能直接念出来，不用书面语；每个锚点都留钩子，让面试官顺着问；不堆技术名词；结果用相对比例和量级，不报绝对经营数据。CTO 面那版也守这些要求，只是不要求 JD 匹配。

## 二、本轮面试复盘（用户说「本轮面试结束了」）

### 步骤 1：把本轮问答原样归档

**归档位置**：`src/main/resources/qa-notes/`。**按本轮回答该问题时实际命中的 skill 选目录**，不是按问题主题猜：

| 本轮命中的 skill | 归档到 |
| --- | --- |
| `04.项目经验`（含岗位与业务全景、系统构成、项目难点、数字追问） | `qa-notes/16.岗位背景/<公司名>/README.md` |
| 无 skill 命中，靠 steering `01.基础知识` / `AGENTS.md` 的通用规则回答 | `qa-notes/01.基础知识/README.md` |
| `07.CTO面` | `qa-notes/07.CTO面/README.md` |
| `08.HRBP(不带案例)` / `09.HRBP(带案例)` | 对应同名目录的 `README.md` |
| `06.架构设计`、`03.性能优化`、`05.系统设计`、算法与笔试各 skill | 对应同名目录的 `README.md` |

只有 `04.项目经验` 按公司分目录，因为项目题的答法随目标岗位变，需要按公司留档；其余按 skill 归到同名目录，跨公司累积。

跨多个 skill 的一轮面试，按每个问题各自命中的 skill 分别归档，不要合并成一份。公司目录不存在时新建。

**格式照已有文件，不要另创**：

```
# <公司名或场景名> Q&A

## 1. <问题原文>
<回答原文>

## 2. <问题原文>
<回答原文>
```

**原样归档的含义（这条是硬要求）：**

- 问题**逐字照录**，包括错别字、口语、标点，不修正、不润色、不概括
- 回答**照录当时给出的原文**，不重写、不补充、不因为事后发现更好的答法就改掉
- **严格按提问顺序**编号，不按主题重排、不合并相似问题、不删掉答得差的
- 已有文件用追加，序号从现有最大号往后接，不覆盖历史记录

**归档时唯一允许的改动是脱敏**，口径与 `04.项目经验` skill 一致：内部系统代号换成功能描述、同事姓名换成角色代称、内网地址与 Redis key 与 topic 与表名与凭证一律不写。如果某条回答脱敏后就没内容了，保留问题、答案处注明「涉密未记录」。

### 步骤 2：重置「本轮目标岗位」

把 `.kiro/steering/01.基础知识.md` 的「本轮目标岗位」十一项全部还原成 `TODO（面试前填写）`，让下一轮重新填。

**`08/09.HRBP` 里按轮次填过的话术也一起还原成 `TODO（面试前填写）`**。

还原后 grep `TODO（面试前填写）` 确认都回来了，再 grep 一遍确认没有残留的上一轮公司名、岗位名、案例映射——**残留比不填更危险**，会导致下一轮按上一家的岗位选案例。

只重置字段值，不要删除这一节、不要改字段名。

### 交付前自查

- [ ] 问答按原顺序编号，问题与回答均为原文
- [ ] 追加而非覆盖，序号接在历史记录之后
- [ ] 已脱敏：无内部代号、无同事姓名、无内网地址与凭证
- [ ] 「本轮目标岗位」各项 TODO 均已还原（含「本轮面试轮次」「本轮面试官定位」），`08/09.HRBP` 里按轮次填过的话术也已还原，且无上一轮残留
