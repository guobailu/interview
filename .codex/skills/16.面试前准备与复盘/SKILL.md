# 面试前准备与复盘

## 触发条件

自动触发，但入口窄，只认下面两类指令：

1. **面试前**——用户发来一份新岗位 JD，且要求做面试前的准备工作（如「帮我做面试前的准备工作」「按这个 JD 帮我准备」）→ 执行「一、面试前准备」。
2. **面试后**——用户说「本轮面试结束了」（或同义的「这轮面完了」「面试结束了」）→ 执行「二、本轮面试复盘」。

用户点名本 skill 名称或目录名时也激活。

**不要因为用户提到简历、JD、面试、岗位这些词就激活。** 本技能会实际改动文件（改简历副本、填写与重置 steering、写归档），误触发的代价比漏触发大。两种典型的不该激活：

- 用户只贴了一份 JD、没说要准备 → 先问一句要不要跑准备流程，不要自己开始。
- 用户在问某道面试题该怎么答 → 那是 `04.项目经验` 等答题类 skill 的事，与本技能无关。

---

## 一、面试前准备（收到新 JD + 「帮我做面试前的准备工作」）

先做一件事：从 JD 里提取出「公司名、目标岗位、岗位职责、技术关键词、业务领域、上下游团队」六项，作为后续三步的共同输入。公司名用于命名简历副本与问答归档目录，其余五项用于填 steering 和写自我介绍。

### 步骤 1：补简历里缺失的麦当劳部分

**输出到 `.private/简历-<公司名>.md`，不要改基线。** `.private/简历-上次跳槽版.md` 是基线原件，任何情况下不得修改。做法是完整复制基线，再在副本上改。生成的简历不进 public 仓库（`.private/` 已 gitignore）。

改动前先读三个事实底座，不要凭印象写：

- `.private/项目经验库.md` 第二章「麦当劳中国」——素材来源
- `.private/面试主线整合版.md`——问题到案例的映射、归属口径
- `.private/简历-上次跳槽版.md` 文末「校对清单」——已定的时间线、姓名、归属、数字口径

**硬性约束：**

- **不动格式。** 层级、标号、加粗位置、「项目简介／技术组成／收益」这套字段名，全部沿用基线里天猫好房那条的写法。只增内容，不改结构。
- **两处都要补。** 一是 `## 工作经验` 下的麦当劳条目（bullet 补强，条数与基线量级一致）；二是 `## 近期主要项目经验`，把麦当劳**插到第 1 项**，天猫好房及之后顺延。
- **重 Loyalty，轻 CNN。** 本人是 Loyalty 组负责人，简历重心必须在 Loyalty：会员营销活动、玩法容器、券与促销、任务编排、发奖、微页面。CNN 私域触达只作为佐证出现。
- **CNN 占比按字数卡，不超过 20%。** 即麦当劳整段（工作经验 bullet + 项目经验条目）里 CNN 相关字数 ≤ 总字数的 20%；350 字的详细介绍部分里，CNN ≤ 70 字。写完要自己数一遍。
- **项目简介段写四件事，并留钩子**：项目定位（是什么、在整个链路里的位置）、面向人群（对客还是对内、什么规模量级）、业务难点、亮点设计。**钩子指的是点到而不展开**——只报结论和技术名词，把「怎么做到的」留给面试官问，他一问就转 `04.项目经验` skill 接着答。
- **详细介绍部分不超过 350 字**（项目简介之后的所有子条目与收益合计）。只列重点，一眼能抓住。宁可少列两条，不要写满。

**口径纪律（必须遵守，来源见校对清单）：**

- 图片广告的 30000 QPS 只能写「设计目标 6 倍容量」，原文档写的是「压测待评估」「P99 不劣于老接口才继续」，不得写成已达成。
- AI／MCP 必须区分「已落地」（对客 MCP Skill）与「设计方案」（两份 Agent 方案），不能混作一谈。
- OKR 里的目标值属于待达成，不能当成果写。
- 用户规模按三层口径：会员 3.3 亿是去重实名，可触达账号 6 亿量级，10 亿是容量设计基线。简历上用哪个都行，但要跟校对清单里的答辩口径对得上。

### 步骤 2：填写 steering 的「本轮目标岗位」

**只有一个填写处**：`.kiro/steering/01.基础知识.md` 的「本轮目标岗位」一节。它是 `inclusion: auto`，每轮对话都注入，所以 04、06、07、08、09 全部能读到，不需要在各 skill 里各存一份。

按 JD 填九项：招聘企业、目标岗位、岗位职责、候选人定位、岗位技术关键词、业务高频词、上下游协同团队、本轮优先案例、本轮要避开的。

填写要点：

- **岗位职责**别照抄 JD 全文，提炼 2 到 4 条、每条一句话，**保留 JD 原词**（面试官会用自己 JD 里的词提问）。
- **业务高频词**是答题时要主动用的词，从 JD 里摘，不要用自己团队的内部叫法。
- **本轮优先案例**填 3 到 5 条「问什么 → 挑哪个案例」的映射，案例必须来自 `.private/项目经验库.md`，不能凭印象编。挑的时候优先找与 JD 技术关键词重合度最高的，同时**主动找出与 JD 领域直接对应的那一段经历**（哪怕体量小、年代久），一条直接接点比三条间接佐证更有用。
- **本轮要避开的**要写清「哪些方向没做过」+「被问到怎么答」，避免临场硬撑。

填完 grep 一遍 `TODO（面试前填写）`，确认 `.kiro/` 下已无遗漏。

### 步骤 3：写一版契合 JD 的自我介绍

放进 `.private/简历-<公司名>.md` 末尾，单开一节「自我介绍」。给两个版本：

- **30 秒版**，约 120 字，用于对方说「先简单介绍下自己」
- **90 秒版**，约 350 字，用于对方说「详细讲讲你的经历」

两版都按四段走：

1. **一句话当前定位**——现任职级与负责的域，带上业务量级
2. **两个与 JD 最强匹配的锚点**——从 JD 的技术关键词和业务领域里挑最硬的两项，各配一个自己的真实项目，一句话带结果
3. **一个反差亮点**——JD 没要求但对方一定感兴趣的，用来制造记忆点（如资金安全体系、AI/MCP 落地、团队级机制建设）
4. **一句为什么是这家**——必须落到 JD 里的具体业务，不能是「贵公司平台大」这类通用话

要求：口语化，能直接念出来，不用书面语；每个锚点都留钩子，让面试官顺着问；不堆技术名词；结果用相对比例和量级，不报绝对经营数据。

### 交付前自查

- [ ] 基线 `.private/简历-上次跳槽版.md` 未被修改
- [ ] 麦当劳已插到「近期主要项目经验」第 1 项，格式与天猫好房条目一致
- [ ] CNN 字数占比 ≤ 20%，详细介绍 ≤ 350 字（实际数过）
- [ ] 30000 QPS 写的是「设计目标」；AI 部分区分了已落地与设计方案
- [ ] grep 确认已无遗漏的 `TODO（面试前填写）`
- [ ] 自我介绍两版都用了 JD 原词，且落到了具体业务

## 二、本轮面试复盘（用户说「本轮面试结束了」）

### 步骤 1：把本轮问答原样归档

**归档位置**：`src/main/resources/qa-notes/`，与 `.kiro/skills/` 同构的目录树。按本轮实际用的 skill 选目录：

| 本轮场景 | 归档到 |
| --- | --- |
| 岗位背景类提问 | `qa-notes/16.岗位背景/<公司名>/README.md` |
| CTO 面 | `qa-notes/07.CTO面/README.md` |
| HRBP 面 | `qa-notes/08.HRBP(不带案例)/README.md` 或 `09.HRBP(带案例)/README.md` |
| 项目经验类 | `qa-notes/16.岗位背景/<公司名>/README.md` |
| 架构设计、性能优化、算法、笔试等 | 对应同名目录的 `README.md` |

跨多个场景就分别归档到各自目录，不要合并成一份。目标公司目录不存在时新建。

**格式照已有文件，不要另创**：

```
# <公司名或场景名> Q&A

## 1. <问题原文>
<回答原文>

## 2. <问题原文>
<回答原文>
```

**原样归档的含义（这条是硬要求）：**

- 问题**逐字照录**，包括错别字、口语、标点，不修正、不润色、不概括
- 回答**照录当时给出的原文**，不重写、不补充、不因为事后发现更好的答法就改掉
- **严格按提问顺序**编号，不按主题重排、不合并相似问题、不删掉答得差的
- 已有文件用追加，序号从现有最大号往后接，不覆盖历史记录

**归档时唯一允许的改动是脱敏**，口径与 `04.项目经验` skill 一致：内部系统代号换成功能描述、同事姓名换成角色代称、内网地址与 Redis key 与 topic 与表名与凭证一律不写。如果某条回答脱敏后就没内容了，保留问题、答案处注明「涉密未记录」。

### 步骤 2：重置「本轮目标岗位」

把 `.kiro/steering/01.基础知识.md` 的「本轮目标岗位」九项全部还原成 `TODO（面试前填写）`，让下一轮重新填。只有这一处要重置。

还原后 grep `TODO（面试前填写）` 确认九项都回来了，再 grep 一遍确认没有残留的上一轮公司名、岗位名、案例映射——**残留比不填更危险**，会导致下一轮按上一家的岗位选案例。

只重置字段值，不要删除这一节、不要改字段名。

### 交付前自查

- [ ] 问答按原顺序编号，问题与回答均为原文
- [ ] 追加而非覆盖，序号接在历史记录之后
- [ ] 已脱敏：无内部代号、无同事姓名、无内网地址与凭证
- [ ] 九项 TODO 均已还原，且无上一轮残留
